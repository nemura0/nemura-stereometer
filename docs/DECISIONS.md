| 2026-11-21 | Transport slots | A slot's state is its 64-bit owner word: 0 = free, else the owner's instance id, whose high 32 bits are the owner's pid (the low 32: a per-process counter from a random start). | 2026-11-22 | Playhead | `nmr::Playhead` (`Sources/Core/include/nmr/playhead.h`) estimates the writer as a steady clock: sample rate × time plus the highest offset (count − rate × time) seen when a block arrives, settling down at 0.1 % of the rate (follows a writer clock up to 1000 ppm slow), re-anchored when an offset falls more than 2 blocks below it (a source stopped and resumed), and never more than one block past what arrived. The IO proc turns off the clock device's own input streams (`kAudioDevicePropertyIOProcStreamUsage`): measured with VB-Cable as the clock, `kAudioProcessPropertyIsRunningInput` goes from 1 to 0, so the app does not count as using the microphone; the HAL still hands turned-off streams a scratch buffer. Blocks capture C++ references by reference: every capture block holds a `weak_ptr` copy (`weak_from_this()`). |

| 2026-11-22 | Permission flow | No public call reports the audio-capture grant, and a denied grant delivers exact zeros, never an error. So the capture watches the signal (`SignalWatch`): only exact zeros for 4 s without a break while another process runs output on the tapped device (`kAudioProcessPropertyIsRunningOutput`, then `kAudioProcessPropertyDevices` on the output scope; this process left out), with no sound ever seen, reads as "likely denied"; a look that finds no frames at all (a stalled or rebuilding tap) is no evidence and breaks the count, and a new tap starts it again; anything but an exact zero means granted, latched. The check runs on the capture queue every 0.5 s and stops for good once sound arrives; once a run has seen sound (`captureSoundSeen` in the app's defaults) later runs do not watch at all, so a stopped DAW (an engine running zeros) never raises the notice for a working grant. The notice says "may be off" and the help names that case: the heuristic cannot tell a denied grant from an app playing digital silence. Private TCC calls (`TCCAccessPreflight`) were not used. The help names the current labels ("Screen & System Audio Recording", "System Audio Recording Only") and opens `Privacy_AudioCapture` (both read from this Mac's System Settings); on older releases down to 14.2 they are unverified. The notice is laid out by frames, never constraints, so it can never set the window's size; its height follows its width and the whole message fits at the 160 pt minimum (unit test). The first-run window shows once, before the first capture (and its macOS prompt); the quick menu's "Audio Permission…" opens the help at any time. |
